Sample data

Five datasets with a known answer key. Real attribution data has no ground truth — you can compare models to each other, but never tell which one was closer to right. These are simulated from explicit channel influence weights, so the truth is recorded and every model gets scored against it.

Two files per dataset, and why

The events, and the answer key. They are separate on purpose.

The events file is a log of what happened. One line per event: who, when, what they did, which channel, how much money. Hundreds of thousands of lines. This is what you feed into a model.

The answer key is a handful of lines — one per channel, with the share of influence that channel genuinely deserves, totalling 100%. This is the real one for The last-touch trap:

paid_social38.8%
video24.7%
display18.4%
email11.1%
branded_search7.0%

It is a second file rather than an extra column because the two have different shapes. The events file has one row per event; the answer has one row per channel. And the answer is not a property of any single event — "paid social deserves 38.8%" is not true of one particular ad impression on a Tuesday, it is true of the dataset as a whole. There is no column in a log of events where a statement about the whole log could sit.

Where does the answer come from, if real data has no answer?

From the fact that this data was invented. Before any events existed, the rules were chosen: paid social will be powerful, branded search will appear constantly and do almost nothing. Then the generator manufactured events obeying those rules. Those original choices are the answer key, and they live in src/touchpath/datasets.py as two numbers per channel — how often it appears, and how strongly it moves the odds of converting.

That is exactly what real data can never have. Nobody chose the rules behind real customer behaviour, so nobody can look them up, and no vendor can be contradicted when they tell you their number. It is the whole reason simulated data is worth the effort: it is the only setting in which an attribution model can actually be marked right or wrong.

How to score a model against it

Run your model on the events, convert its output to shares of the total, and compare channel by channel. Mean absolute error across channels is the headline number.

Also check the ordering. A model that is off by a few points everywhere but ranks the channels correctly is more useful for budgeting than one with a lower error that puts the wrong channel on top — because budget decisions are made from the ranking, not the decimals.

If you run a dataset here rather than downloading it, this comparison is done for you: the results table shows a Truth column beside the seven model columns.

One thing the answer key is not

It is not how often each channel appeared. Influence and prevalence are different quantities, and confusing them is the most common way attribution goes wrong. In The last-touch trap below, branded search turns up in nearly two thirds of journeys and is worth about 7%. Every model in the suite over-credits it — including the counterfactual ones — because a channel present in almost every journey looks indispensable to any method that asks what happens when you remove it.

Using them elsewhere

They are ordinary event files, not a proprietary format.

Each download is a JSON array of event records with the field names the ingest layer expects — user_id, timestamp, event_type, channel, revenue. Load them into anything.

The answer key is a small separate JSON object at /datasets/<slug>.truth.json, carrying the per-channel shares plus a note on what the measure means and how to score against it. Fetch it alongside the events if you are benchmarking your own model elsewhere.

To produce them locally instead of downloading, or to regenerate with different parameters:

pip install -e "." then touchpath datasets --out datasets/

The seeds are fixed, so the same slug always produces the same data. A number you quote from a sample stays true.
